# AI 转型路线（目标：2027 年 3 月）

这不是“从零学完所有 AI”，而是一条面向有 Java 后端经验的工程师的转型路线：在 16 周内形成 **机器学习基础 + 深度学习实践 + LLM 应用工程 + 可展示作品集**。

## 你的起点与定位

- 2017 年本科毕业；有两年多 iOS 开发经验，之后转 Java 后端。
- 已有高等数学、线性代数、概率统计基础，也练习过 Python 和机器学习。
- 最适合的切入方向：**AI 应用/机器学习工程师（偏后端与平台）**，而不是一开始竞争纯算法研究岗位。
- 现阶段最重要的差异化：把模型能力做成可靠的服务，能完成数据、训练、评估、部署、监控的闭环。

## 2026-11 至 2027-03 的阶段目标

| 阶段 | 时间 | 必须产出 |
|---|---|---|
| 1. Python 与数据工程 | 11 月第 3-4 周 | 一个规范 Python 项目：类型标注、pytest、日志、配置、Docker |
| 2. 经典机器学习 | 12 月 | 一个端到端预测项目：特征工程、交叉验证、指标、错误分析 |
| 3. 深度学习 | 2027 年 1 月 | PyTorch 项目：训练循环、实验记录、迁移学习、模型服务 |
| 4. LLM 应用工程 | 2027 年 2 月 | RAG 知识库或 Agent 项目：检索评估、引用、权限、API、观测 |
| 5. 求职与强化 | 2027 年 3 月 | 2-3 个可演示项目、技术文章、简历、面试题与模拟面试 |

## 每周安排（建议 15-20 小时）

- 6 小时：系统学习与笔记（概念必须转成自己的代码）。
- 8 小时：项目开发，周末形成一个可运行增量。
- 2 小时：复盘和写作，记录指标、失败实验和下一步。
- 2-4 小时：算法/SQL/Python 面试与英文资料阅读。

每周遵循：`学一个概念 -> 实现一个最小实验 -> 写测试和 README -> 得出一个可验证结论`。不要同时铺开多个框架。

## 技术栈收敛

Python 3.11、uv 或 poetry、NumPy、pandas、scikit-learn、PyTorch、FastAPI、PostgreSQL/pgvector、Docker、MLflow（或 W&B）。LLM 阶段优先使用模型 API，理解原理后再做本地模型；不要把时间消耗在无关的框架切换上。

## 作品集要求

### 项目 A：业务预测服务

选择一个公开数据集（用户流失、订单需求或信用风险），完成数据清洗、基线模型、特征工程、交叉验证、概率校准、错误分析，并提供 FastAPI `/predict` 接口和 Docker 启动方式。README 必须写清楚数据切分、指标选择和已知局限。

### 项目 B：PyTorch 文本/图像项目

使用迁移学习完成分类或文本匹配；保存训练配置和最佳模型，提供可复现实验脚本、混淆矩阵/误差样例，以及一个推理 API。重点展示你能定位过拟合、数据泄漏和分布变化。

### 项目 C：企业知识库 RAG

针对 Java/后端开发文档构建问答系统：文档解析、切分、向量检索、重排、带引用回答、拒答策略、离线评估集和延迟/成本统计。支持增量更新，并说明为什么某些问题不能回答。

## 你必须掌握的面试主线

- 机器学习：偏差-方差、正则化、数据泄漏、交叉验证、类别不平衡、阈值与校准、特征重要性。
- 深度学习：反向传播、优化器、归一化、注意力、Transformer、微调与推理优化。
- LLM：token、上下文、embedding、RAG、幻觉、评估、提示注入、成本和延迟。
- 工程：API 设计、异步任务、缓存、容器化、模型版本、灰度发布、监控与回滚。

## 第一个月的具体任务

1. 建立 `src/`、`tests/`、`notebooks/`、`data/`、`docs/` 目录，并配置 lint、格式化和 pytest。
2. 用 NumPy 手写线性回归和逻辑回归，再用 scikit-learn 复现并比较。
3. 选择项目 A 数据集，完成数据字典、基线模型和首版评估报告。
4. 发布第一篇文章：解释一次失败实验，而不是只展示最高分。

## 判断是否达标

到 2027 年 3 月，你应能在 10 分钟内讲清一个项目的业务问题、数据、基线、关键实验、指标、失败案例、部署架构和下一步；能在 1 小时内用 Python 完成数据处理和模型评估；能独立把一个模型封装成服务并说明它的风险。

## 协作方式

后续每次可以把本周代码、实验结果或卡点发给我。我会按“概念理解、代码质量、实验设计、工程化、面试表达”五个维度给出反馈，并把任务拆成下一周可完成的清单。
